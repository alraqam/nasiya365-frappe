# Обязательный IMEI при приёме телефонов — дизайн

**Дата:** 2026-09-03
**Область:** `StockEntry.validate()` (приём на склад)
**Тип:** новая проверка (защита от бага), изменение поведения приёма

---

## Проблема (корень инцидента STE-2026-00636)

Телефон можно оприходовать на склад **без IMEI** (поле `imei` на Stock Entry Item не
обязательно). А списание со склада работает **только по IMEI** (`refresh_stock_entry_business_status`
при отсутствии IMEI делает `if not serials: return`). Итог: «безымянный» телефон навсегда
застревает как «В наличии», даже когда продан — что и произошло с STE-2026-00636.

## Решение (согласовано)

При приёме телефона IMEI **обязателен**. Тогда безымянный телефон просто нельзя сохранить.

- **Критерий «телефон»:** товар с `allow_installment=1` (на данных: все телефоны имеют этот
  флаг, все IMEI в поступлениях — у таких товаров; аксессуары `allow_installment=0`).
- **Где:** `StockEntry.validate()`, только `entry_type='Поступление'`.
- **Аксессуары** (`allow_installment=0`) — без изменений, IMEI не требуется.
- **Уникальность IMEI НЕ проверяем** — глобальная уникальность сломала бы легитимный
  **выкуп телефона обратно** (тот же IMEI законно приходуется повторно после продажи).
  Только обязательность (IMEI не пустой).

### Логика

Новый метод `StockEntry._require_imei_for_phones()`, вызывается в `validate()`:
```
if entry_type != "Поступление": return
для каждой строки items:
    если товар (Product.allow_installment == 1) и imei пустой:
        frappe.throw("Укажите IMEI для телефона «{название}» (строка {idx}).
                      Без IMEI телефон невозможно списать со склада при продаже.")
```

## Что НЕ меняется

- Аксессуары; типы движений Отпуск/Перемещение/Корректировка (только Поступление проверяем);
- существующие поступления (проверка только при сохранении/приёме нового или редактируемого);
- уникальность IMEI (сознательно не трогаем — конфликт с выкупом).

## Тесты

Прямой вызов `_require_imei_for_phones()` на in-memory Stock Entry:
1. Поступление телефона (`allow_installment=1`) без IMEI → **throw**.
2. Поступление телефона с IMEI → ОК.
3. Поступление аксессуара (`allow_installment=0`) без IMEI → ОК.
4. Тип «Отпуск» (не Поступление) с телефоном без IMEI → ОК (не блокируем).
5. Смешанная строка: телефон с IMEI + аксессуар без IMEI → ОК.
