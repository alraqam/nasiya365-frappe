## 2. Созданные компоненты и функции

- **Адаптер** `pnl_adapter.js`: `buildViewModel(raw)` (сырой ответ `get_profit_summary` → `{summary, sales{cash,installment,total}, recognized, basis}`) и `formatMoney(value)` (единый формат: `$3 510.00`, `$0.00`, `—`, `−$120.00`). Чистые функции, dual-export (browser global + CommonJS для node-тестов). Никакой новой финансовой логики — только раскладка ключей и две проверенные производные («Общая прибыль рассрочки» = маржа+проценты; «Покрытие себестоимости» = собрано − признанная прибыль, ровно как в старом отчёте).
- **Страница** `profit_and_loss.js` (класс `nasiya365.ProfitAndLoss`): фильтры (Дата с/Дата по/Филиал + «Сформировать отчёт»/«Обновить»/«Экспорт CSV» + «Обновлено: …»), 3 карточки, Таблица 1 «Продажи, оформленные за период», Таблица 2 «Поступления и заработанная прибыль», инфо-блок базы прибыли (§8), тултипы (§11), состояния загрузка/пусто/ошибка (§12), клиентский CSV-экспорт. Данные берутся ТОЛЬКО из `nasiya365.api.profit.get_profit_summary` (бэкенд не менялся).

## 7. Известные ограничения

- **Кеш-бастинг новых ассетов.** `pnl_adapter.js` и `pnl.css` отдаются как «сырые» файлы из `/assets/...` (не content-hashed). Это сделано намеренно, чтобы страница работала и на dev (где бандл не пересобирается — нет node), и на проде без пересборки. Минус: при будущих правках эти два файла кешируются браузером по фиксированному URL. **Перед/во время прод-деплоя** стоит либо свернуть их в content-hashed бандл (`nasiya365.bundle.js/.css`), либо полагаться на version-nudge/SW для сброса кеша.
- Инфо-блок «Процентный доход: не входит в итог» показывается и когда проценты просто = 0 (флаг `interest_in_profit` завязан на величину) — унаследовано от семантики бэкенд-флага, на число не влияет. Не редизайн-баг.
- Старый Script Report «Profit and Loss Summary» остаётся зарегистрированным (как fallback/экспорт). При желании его можно скрыть из меню отдельной задачей.
